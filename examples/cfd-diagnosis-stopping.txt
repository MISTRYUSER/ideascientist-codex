Problem definition:
Develop an LLM-agent decision method for diagnosing, locally repairing, and deciding when to stop existing CFD simulations in reproducibility/regression settings. The thesis topic is “面向 CFD 仿真的大模型智能体诊断修复与停止决策研究”. Use this existing topic as the fixed research scope and propose one defensible, implementable refinement with falsifiable experiments.

The physical task is a fixed 2D NACA0012 case, angle of attack 0 degrees, Reynolds number approximately 6e6, Spalart–Allmaras turbulence model, and OpenFOAM Foundation 12. Inputs are the current case configuration, solver logs, task requirements and available reference data; the agent cannot access the hidden healthy configuration or injected fault labels. Repairs must be minimal local edits under a file/field whitelist, retaining legitimate changes. Do not replace the task with new-case generation, general CFD discovery, 3D work, fine-tuning or model training.

Challenge:
Solver completion, numerical convergence, and even agreement with selected reference outputs can coexist with a wrong physical configuration. We need reliable decisions to inspect, edit, run a bounded solver, or stop under incomplete/conflicting evidence and compute budgets. Detecting unknown evidence, invalidating stale evidence after edits, choosing informative low-cost checks, avoiding false completion claims and unnecessary modification, and stopping at the right time are the principal difficulties.

Existing planned method and experiment constraints:
- Diagnostic items have four states: pass, fail, unknown, not applicable, accompanied by original evidence. Approximately fifty items come from task requirements, not fault labels. Platform rules generate these states; the LLM selects actions and cannot rewrite the states. Unknown sources include missing fields, unparseable syntax and conflicting evidence. After an edit, related cached evidence becomes invalid until checked again. Record action consequences.
- Actions: read-only check, whitelisted local patch, bounded solver run, or stop. Preserve independent enforcement and independent acceptance; the agent's own declaration is never proof of correctness.
- Tasks: single faults, sampled two/three-fault combinations, healthy/legal variants, and must-stop controls (zero solver budget, missing reference data, protected-field faults, ambiguous evidence). Mechanisms include missing dictionaries, boundary type/value, viscosity/material parameters, force-axis errors, and boundary-name mismatch. Hidden healthy configurations are for evaluation only.
- Baselines: a strong deterministic rule method, a generic agent, and the proposed agent under matched visible information and budgets. Compare four-state representation against removal of unknown, binary states and equal-length free-text records; do not confound representation with more information or longer context.
- First phase is static configuration acceptance and DOES NOT establish the later method's effects. Later closed-loop acceptance independently checks execution, numerical convergence, physical configuration and reference agreement. Legal edits, guard rejections, attempted vs actual modifications, invalid trials/timeouts and reruns must be accounted for separately.
- Research questions: RQ1 under fixed observations, does explicit unknown improve single-step repair decisions? RQ2 can adaptive checks reduce solver cost while maintaining acceptance success within a preregistered noninferiority margin? RQ3 what fails on unseen fault mechanisms, severity and combinations? Do not merge task types into a shared success-rate denominator. Hold out mechanisms before development and report uncertainty using tasks as the independent units.
- A healthy baseline and an experimental platform exist according to the supplied proposal. Pilot/debugging records demonstrate feasibility, not comparative method efficacy. Treat all baseline numerical claims in the source as author-provided, not independently verified. Retain strong rule baselines even if they outperform the agent and limit conclusions to this fixed task.
